# 媒体人家（mtrj.vip）自动发稿

把一篇本地 Markdown 稿件，通过「媒体人家」平台自动下单发布到**用户指定的任意媒体渠道**。

**核心链路**：本地 `.md` → DOCX → 上传 → 填标题 → **选媒体（名称运行时指定）** → 下单扣款 → 归档到「已发」。

---

## ★ 最重要的设计原则：媒体名称不写死

**本 skill 不绑定任何特定媒体。** 每次发布时由用户告诉我们这次投放到哪个媒体，脚本按名称（或 ID）去平台上匹配。

- ❌ 不要假设一定是「博客园」——那只是一次举例。
- ✅ 用户说「发到自动化网」就用 `自动化网`；说「发到金山网」就用 `金山网`；说「发到南方科技」就用 `南方科技`。
- ✅ 媒体名称可能不完整（如只给「自动化」），脚本支持**模糊匹配**。
- ✅ 同名媒体（如「金山都市」有浙江/上海两条）脚本会**自动提示消歧**，绝不擅自乱选。

---

## 一、适用场景

- 用户有一批 SEO/GEO 稿件（`*.md`），需要投放到「媒体人家」平台的**某个媒体渠道**。
- 需要批量、可重复地发布，而不是每次手动操作网页。
- 发布完成后希望自动：① 把发布信息记录到飞书表格；② 把稿件从「稿件」目录移到「已发」目录。

**不适用**：直接发布到某个媒体的官网（如 cnblogs.com）——那需要该站自己的账号。本 skill 走的是「媒体人家」这个第三方软文平台。

### 步骤 1 · 人工登录（仅在首次 / 掉线时）

> **★ 硬性规则（2026-11-10 起）：登录全程由本人手动完成。**
> 本 skill **不自动过滑块、不自动填写账号密码、不识别验证码、不读取任何凭据文件**。
> 曾存在的 `mtrj_login_auto.js` / `mtrj_guard.js` / `guard_solve_pos.py` 已移入 `scripts/_deprecated/` 并停用；
> `mtrj_publish.js` 也不再调用 `~/.mtrj/ensure_login.js` 自动续登。任何情况下都不得私自恢复这些能力。

```bash
cd "$HOME" && node <skill>/scripts/mtrj_login.js            # 默认 profile：~/.mtrj/browser-profile
# 可选：--profile <目录>   --timeout <分钟，默认 10>
```

**会弹出一个可见的 Chrome 窗口，由本人完成：**

1. 若出现 WAF「**安全验证**」旋转拼图滑块 → **手动拖动**通过；
2. 手动点击登录，在页面上**手动输入账号 + 密码 + 图形验证码**；
3. 进入后台（看到「您好：xxx」）即成功。

脚本每 3 秒轮询一次页面内容，检测到后台字样后**自动导出 `storage-state.json` 并关闭窗口**；超时 10 分钟退出（退出码 2）。

> ⚠️ **登录入口**：本站没有独立的登录页。实测 `/Manage/Login.aspx`、`/index.aspx` 都返回
> `title=错误页面`（表现为「404」），**不要**再把登录入口指向这些地址。
> 正确做法是打开首页 `https://www.mtrj.vip/`，登录框在首页与 `/Manage/` 页内。

> **退出登录**：`POST /IHttpHandler/Handler_Menber_Login.ashx`，`typename=quit` → 返回 `ok`（见 `mtrj_logout.js`）。
> 该 `quit` 只注销**当前浏览器上下文所持会话**；要注销某个 `storage-state.json` 里的旧会话，
> 必须先把它的 cookie 注入上下文再调 `quit`。否则旧会话仍然有效。

### ★ WAF 滑块（`_ok5_` 过期后必然遇到）

站点前置 WAF，放行凭据是 **`_ok5_` Cookie（约 7 天）**。没有它时**任何页面**都会被换成
「安全验证」页（`<script src="/_guard/html.js?js=slider_html">`，标题 `安全验证`）——
**这是旋转拼图滑块，不是普通右滑**。

**处理方式：由真人在弹出的窗口里手动拖动完成。** 脚本不做任何自动识别或自动拖拽。

排障提示（仅供理解现象，不用于自动过关）：

- 若窗口里一直停在「安全验证」，说明 `_ok5_` 已过期，手动滑一下即可继续；
- 若页面显示 `错误页面`，通常是打开了不存在的地址（如 `Login.aspx`），不是账号问题；
- 手动过关后，登录脚本会把新的 `_ok5_` 连同会话 Cookie 一起写进 `storage-state.json`。

### 5.5 ★ 新记录置顶机制（重要，别搞错）

**需求**：新写入的记录要出现在表格**最上面**，而不是追加在最下面。

**原理限制（务必理解）**：飞书多维表格的记录在存储上是**追加**的——`+record-batch-create` 只能在末尾追加，官方 API 没有"插入到第 N 行"的能力。所以"新行在最上面"只能通过**视图排序**实现，排序只影响显示、不改变存储顺序。

**本表采用的方案**（已完成配置，不要重复建）：

1. 表中有一个字段 **`序号`**（类型 `auto_number`，自动编号，规则 `0001`~），字段 ID `fld9i1TuXa`。
   - 它是**系统字段**：创建/删除记录时由系统自动赋值，**不可手改、不可清除、不会重复**，因此是天然稳定的排序键。
   - 历史 85 条已按当时行序得到 `0001`~`0085`，最新的 geo-01/geo-02 是 `0084`/`0085`。
2. 视图「表格」(`vewIN6vcd5`) 的排序设置为 **`序号` 倒序（desc=true）** → 编号最大的（=最新写入的）永远排在最上面。
3. `序号` 字段已从可见列中**隐藏**（不占版面），仅在排序中生效；可见列仍是原来的 7 列。

**因此：新增记录只要走正常的 `+record-batch-create` 即可自动置顶，不需要任何额外操作，也不需要手动移动行。**

**若干坑**：

- ❌ **不要**用「创建时间」当排序键——那是我们写入的**订单创建时间**，语义与"写入先后"不同，且可能缺失。
- ❌ **不要**尝试用 `+record-batch-create` 的参数控制插入位置——不存在该参数。
- ❌ **不要**去修改 / 删除 `序号` 字段，也不要把它加回可见列；改动会重排全部历史编号。
- ⚠️ 若视图排序被清空（`+view-get-sort` 返回 `[]`），新记录会回到末尾。恢复命令：

```bash
lark-cli base +view-set-sort --base-token BMo2bp0DJap41TsjpLZcCfz7nmb \
  --table-id tbl6DPyhsVQjLRhB --view-id vewIN6vcd5 \
  --json '{"sort_config":[{"field":"序号","desc":true}]}' --as user
```

**新增记录自查**：写入后确认 `序号` 是当前最大值，且该行在视图排序（序号 desc）下位于首位。

## 八、关键机制说明（排障必读）

### 7.1 为什么用浏览器自动化而不是 API？
该平台**没有公开 API**。后台接口（`Handler_Article.ashx`、`Handler_MediaCart.ashx` 等）依赖浏览器页面上下文中的临时稿件句柄 `Hid`；用 curl/requests 独立请求会丢失该句柄，报「请先发布文章内容」。**必须用真实浏览器连续上下文**。

### 7.2 为什么登录态要用 storageState 而不是 Profile 的 Cookie 库？
`ASP.NET_SessionId` 是**会话级 Cookie（`expires=-1`）**，Chrome 关闭时**不会写入 Cookies 数据库**。而 `ctx.storageState()` 会把它**完整导出**。因此发布脚本每次启动后会 `ctx.addCookies(storageState.cookies)` 显式注入。

### 7.3 选媒体是怎么实现的？
平台页面有 JS 函数 `CheckMedia(Mid)`，会 POST `Handler_Media.ashx`（`typename=checkMedia&Mid=<ID>`）把媒体加入购物车。
脚本优先用页面复选框勾选；若该媒体不在当前页（例如用 `--media-id` 直连时），会**直接调用 `CheckMedia(ID)`**，仍能正确加购。

### 7.4 会「一段时间不操作自动退出」吗？
**实测**：以 60 秒间隔连续探测后台接口 13 次（跨 12 分钟），**全部有效**——期间无登录动作。
**结论**：持续有请求 → 会话保持；只有**长时间完全静默**才会超时。
**策略**：批量发布期间自然产生请求，通常不掉线；两篇间隔超过 ~15 分钟空闲则先 `--dry-run` 探活。掉线重跑 `mtrj_login.js` 即可。

## 十、注意事项

1. **媒体每次指定**：不要把某个媒体当成默认；每次按用户当次要求传媒体名。
2. **钱**：正式发布扣款，务必先 `--dry-run` 验证，并与用户确认单价。
3. **重名必须消歧**：遇到多条同名（不同地区/不同价位）时，先跟用户确认要哪一条，再用 `--region`/`--index` 指定。
4. **标题长度**：脚本自动取 H1 作为标题，超过 40 字会截断到 38 字。
5. **相关阅读**：脚本会自动剥离稿件末尾的「## 相关阅读」板块（避免本地死链），正文链接保留。
6. **凭据**：本 skill **不存储、不读取、不使用任何账号密码**；登录完全由本人手动完成，脚本只保存会话 Cookie（`storage-state.json`）。
7. **登录＝人工**：任何人（包括后续的 AI 会话）都不得为本 skill 添加自动过滑块、自动填表或验证码识别逻辑；如确需恢复，必须由用户明确要求后再改。
7. **飞书同步**：发布后按订单号同步；拿不到的信息（如未收录链接）留空，不编造。
8. **并发**：不要并行运行多个发布脚本（profile 会冲突）。
